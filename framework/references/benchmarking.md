# 评测方法学

> 核验状态：方法学手册（2026-11-20 初版）。默认阈值见 [defaults.md](../conventions/defaults.md#性能评测)。

## 1. 常见指标定义

| 指标 | 含义 | 适用场景 | 方向 |
| --- | --- | --- | --- |
| **TTFT** | Time to First Token，首字延迟 | 文本 / 多模态流式 | ↓ |
| **TTFA / First Chunk** | Time to First Audio，首包音频延迟 | 语音 / 全双工流式 | ↓ |
| **TPOT / ITL** | Time Per Output Token / Inter-Token Latency | 文本生成流畅度 | ↓ |
| **E2E Latency** | 单请求端到端总延迟 | 离线与在线 | ↓ |
| **RTF** | Real-Time Factor，生成耗时 / 音频时长（<1 表示快于实时） | 语音生成、Codec | ↓ |
| **Throughput** | 系统吞吐（tokens/s、req/s、音频秒/秒） | 并发容量 | ↑ |
| **Peak VRAM** | 服务端峰值显存占用 | 并发上限与成本 | ↓ |

分布指标同时关注中位数（p50）与尾延迟（p95 / p99），不以单一均值掩盖抖动。

## 2. 可比性要素

基线与候选对比前，逐项核对：

1. **输入一致**：同一数据集版本、同一冻结选样（如 `selection.json`）、同一 prompt 与多模态文件。
2. **生成参数一致**：温度、top-p、最大长度、停止条件、流式开关一致。
3. **负载模式一致**：并发数、到达速率、预热与重复轮数一致。
4. **环境与硬件一致**：同一 GPU 型号与数量、无其他任务争抢、电源/频率无异常降频、评测客户端版本一致。
5. **加载的代码与登记一致**：服务端进程实际导入的是目标 worktree 与目标 commit。

## 3. 预热、重复与噪声控制

- **预热**：每次服务启动后至少 1 轮预热（涵盖首次编译、缓存与分配），预热数据不进入统计。
- **重复**：每个实验条件至少 `perf.repeats_min`（默认 3）轮，计算均值与变异系数 $\text{CV} = \sigma / \mu$。
- **噪声排查**：当 $\text{CV} > \text{perf.cv\_max}$ 时，先检查共享 GPU 干扰、网络/磁盘 I/O、输出长度波动（采样非确定性或 EOS 漂移）、动态降频，不要在噪声未受控时下结论。
- **判定收益**：按 `perf.gain_min` 判断（默认至少 3% 且超过 2 倍最大 CV）；接近噪声边界的微弱提升记为“未超过测量噪声”，不宣称为有效优化。

## 4. 防回退

优化往往存在权衡（例如吞吐提升但低并发延迟变差，或速度提升但语音自然度下降）。因此每次验证除目标场景外，须核对 `PROJECT.md` 中声明的**关键场景**与**质量指标**。
