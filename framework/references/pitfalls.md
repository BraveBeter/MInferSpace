# 跨项目常见陷阱

> 持续维护。项目遇到新坑先记在 `knowledge/lessons.md`，复盘确认通用后晋升到此处。

| 编号 | 陷阱 | 症状 | 预防与排查 | 来源 |
| --- | --- | --- | --- | --- |
| P1 | **Editable 安装指向错误的 worktree** | 改了候选分支代码，跑出来的数字和基线一模一样 | 每次运行前打印 `import <pkg>; print(<pkg>.__file__)` 并记入 `execution/`；基线与候选尽量使用隔离环境 | 通用实践 |
| P2 | **Benchmark 混入 Profiler 或调试日志** | 吞吐异常低或延迟抖动大，结论失真 | 正式 benchmark 与 profile 严格分开运行；提交前检查关闭 verbose/dump 环境变量 | 通用实践 |
| P3 | **用浮动分支名代替固定起点 commit** | 远端分支推进后，新旧候选的起点不一致，无法复现或对比 | 所有起点、工作项与证据一律记录 40 位完整 commit SHA | 通用实践 |
| P4 | **输入预处理差异伪装成模型数值 bug** | 第 0 层就超差，查了半天 attention 没问题 | 对齐第一步先逐字比较 `input_ids` 和多模态预处理张量，完全一致后再进模型前向 | 通用实践 |
| P5 | **忽略输出长度变化带来的延迟假象** | 端到端延迟“下降 15%”，实际是候选提前输出 EOS 导致生成变短 | 同时核对输出长度分布与正确性/精度，按单位输出指标（TPOT / RTF）交叉检查 | 通用实践 |
| P6 | **在非稳态或高噪声下下结论** | 两次跑同一代码差 4%，却把一次 +3% 的候选当成收益 | 固定预热、至少 3 轮重复、报告 CV；收益必须显著超过噪声 | 通用实践 |
| P7 | **挂载目录文件权限位噪声** | `git status` 显示大量脚本 `100755 -> 100644` 变更 | 在源码仓库本地设置 `core.filemode=false` 并登记到 `worktrees/README.md`，运行脚本显式用 `bash` / `python` | 通用实践 |
| P8 | **运行目录预放文件触发客户端报错** | 评测客户端拒绝写入非空 `--output-dir` | 首次推理前只允许 `execution/` 存在（`ws run-dir` 默认行为），不要预建 `analysis/` 或 README | 通用实践 |
