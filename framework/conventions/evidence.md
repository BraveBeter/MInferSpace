# 证据约定

证据目录（`benchmark-results/`、`profile-results/`、`validation-results/`）保存实际运行的原始结果与执行材料，是结论唯一可信的来源。

## 通用规则

- **只追加**：每次运行使用新目录；重新运行不覆盖旧目录。客户端支持的显式恢复（如 resume）属于同一次运行，按客户端规则在原目录进行。
- **失败也保留**：失败、中断、预算耗尽、未评分的运行继续保留，状态以工具记录为准，并在索引中标注。
- **profile 与正式 benchmark 分开运行**。
- **凭据不落盘**：执行材料只记录所用环境变量名。
- **索引**：每个运行目录都要登记到所在顶层目录 README 的索引表中，并在关联 item.md 的日志里链接。

## execution/ 必备内容

每次运行的 `execution/` 至少包含以下信息。`ws record` 生成 `ws-record.json` 覆盖其中的身份字段，其余按工具原生方式保存。

| 内容 | 说明 |
| --- | --- |
| 命令 | 完整命令行、执行目录、关键环境变量名 |
| 代码身份 | 每个相关仓库的路径、分支、完整 commit、是否有未提交修改（有则保存 patch） |
| 环境 | 环境快照引用；运行时实际加载的关键包路径与版本 |
| 硬件 | GPU 型号与数量、驱动与 CUDA 版本 |
| 配置 | 实际使用的配置副本，含 CLI 覆盖 |
| 输入 | 模型与数据的版本目录、选样或负载描述 |
| 日志 | 服务端与客户端日志（大文件按 `.gitignore` 规则不跟踪，但保留在本地） |

## 分析与结论

- 工具生成的摘要可能被重新生成，人工分析写在独立文件中（benchmark 为 `analysis/`，profile 为 `analysis.md`，验证为 `report.md`），并链接原始证据。
- 分析中区分观察事实与推断。
- 对比必须先确认可比性（数据、参数、硬件、客户端版本、环境），不以目录名相同代替可比性验证。
