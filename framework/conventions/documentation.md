# 文档约定

## 单一事实源

| 信息 | 唯一权威位置 | 其他位置的做法 |
| --- | --- | --- |
| 通用方法、流程、门禁、默认口径 | `framework/` | 链接，不复述 |
| 项目目标、范围、硬件、评测套件、验收口径覆盖、关键场景 | `PROJECT.md` | 链接 |
| 活动工作 | `PLAN.md` | — |
| 工作项详情 | `work/<ID>-<name>/item.md` | 索引只放简述和链接 |
| 源码仓库、worktree、固定起点 | `worktrees/README.md` | item.md 记录本项所用条目 |
| 环境 | `envs/README.md` 及 `specs/`、`snapshots/` | 执行材料引用快照 |
| 模型、数据 | `checkpoints/README.md`、`datasets/README.md` | 配置引用具体版本目录 |
| 可复用配置、辅助脚本 | `configs/README.md`、`scripts/README.md` | — |
| 原始运行结果 | 证据目录 | item.md 只放摘要和链接 |
| 项目知识 | `knowledge/` | 工作项链接条目 |

## 写作规则

- 每条约定简短明确；已有细则由对应文件维护，其他文档链接引用。
- 区分事实、推断、计划和结论；模板预留对应区块，正文中可用“事实：”“推断：”等前缀。
- 示例和占位内容必须标明“示例”或“待填写”，不登记为实际完成的工作。
- 进度与结果如实记录，不将未执行或未验证的事项写为完成；所有数字可追溯到证据。
- 只追加的区块（实验日志、门禁记录、审查记录、lessons）不改写历史，更正时追加说明。
- 中文行文，标识符、命令、路径保留原文。

## 链接与路径

- 本地链接使用相对路径，从所在文件出发；`ws lint` 检查目标存在。
- 指向未跟踪外部目录（如源码 worktree、外部客户端）的链接可能在其他机器上不存在，`ws lint` 报告为提示而非错误；必要时同时给出带固定 commit 的远端链接。
- 框架文档中的示例路径写在代码格式中，不写成链接。
- 重命名、移动或删除文件时同步更新所有引用。

## 登记表

- 目录 README 中的登记表只登记实际存在的条目，空表保留一行 `暂无`。
- 由 `ws` 维护的表格放在 `<!-- ws:<name>:begin -->` 与 `<!-- ws:<name>:end -->` 之间，手工编辑时保留标记。
- 新增或调整文件职责时，同步对应 README 与索引（见[同步矩阵](doc-sync-matrix.md)）。
