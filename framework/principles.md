# 通用原则

所有工作流、约定和模板都从以下原则派生。规则未覆盖的情形，按原则判断并在工作项中写明理由。

## 原则

1. **入口最短，按需加载**：先读入口、项目卡和看板，再按任务和阶段读取所需文档，不一次性加载全部材料。
2. **单一事实源**：每类信息只有一个权威位置（见[文档约定](conventions/documentation.md#单一事实源)），其他位置链接引用，不复制内容。
3. **框架与实例分离**：框架描述方法；项目层描述目标、资产和进度；证据层只追加。
4. **证据驱动**：性能结论来自统一 benchmark；正确性结论来自数值对齐与精度评测；profile 用于定位瓶颈和验证机制。没有证据链接的结论视为未完成。
5. **门禁优先**：阶段推进须满足对应 [gate](gates/README.md)；无法满足时记为 `blocked` 并说明原因，不跳过。
6. **约定写进工具**：命名、索引、链接、状态一致性等可机械检查的规则由 `ws lint` 和 `ws gate` 保证。
7. **区分事实、推断、计划和结论**：文档用对应区块或标记写明性质；示例和占位内容必须标明。
8. **最小改动，范围收敛**：一个工作项对应一个适配目标或一个优化假设；改动只服务于该目标；范围明显扩大时另开工作项。
9. **如实记录**：失败、回退、放弃和未验证事项同样记录并保留证据。
10. **独立审查**：产生代码或结论的工作项在交付前由第二个 Agent 独立审查（见 [code-review.md](workflows/shared/code-review.md)）。

## 规范优先级

冲突时按以下顺序取舍，并在工作项中记录冲突及取舍：

1. 用户的明确指令。
2. 被修改源码仓库自身的规范（`AGENTS.md`、`CONTRIBUTING`、开发者文档），仅约束该仓库内的改动。
3. 实例 `PROJECT.md` 中对框架可覆盖项的设定，以及经用户确认的工作项级覆盖。
4. 本框架。

实例目录 README 只补充项目细则和登记表，不得与框架规则冲突；发现冲突时按[框架改进流程](workflows/shared/retro.md#框架改进)处理。
