# 共享子流程：代码与结论审查

产生代码或结论的工作项在交付前须经过**自审**和**独立审查**。独立审查由第二个 Agent 执行，默认启用。

## 自审

实现者逐项对照 [gates/code-quality.md](../../gates/code-quality.md)，在 item.md 门禁记录中回应每一项。自审通过后再发起独立审查。

## 独立审查

**审查者**：一个新的 Agent 会话（子 Agent），不继承实现者的对话上下文，避免沿用实现者的假设。

**交给审查者的材料**（只给这些，必要时审查者可自行阅读源码）：

- 工作项 `item.md` 与 `design.md`（如有）。
- 源码 diff：`git -C <worktree> diff <起点commit>..<候选commit>`。
- 相关证据目录（对比报告、验证报告）。
- [gates/code-quality.md](../../gates/code-quality.md)、[templates/review.md](../../templates/review.md)、目标仓库规范。

**审查内容**：

| 方面 | 关注点 |
| --- | --- |
| 正确性 | 逻辑错误、边界条件、并发与状态、异常路径、对未声明特性的处理 |
| 范围 | 是否只包含当前工作项所需改动；有无调试残留或无关修改 |
| 规范 | 是否符合目标仓库规范与已有风格；是否复用已有组件 |
| 测试 | 测试是否覆盖改动与回归点；测试本身是否可靠 |
| 结论 | item.md 中每条结论是否有证据支撑；可比性是否成立；数字与证据是否一致；是否夸大适用范围 |

**输出**：按 [templates/review.md](../../templates/review.md) 给出意见，每条标注级别：

- `blocker`：必须修复后才能交付。
- `major`：应当修复；不修复须写明理由并经用户同意。
- `minor` / `nit`：建议项，实现者自行决定并记录处理方式。

## 处理

- 实现者逐条回应（已修复并附 commit / 不采纳及理由），追加到 item.md 审查记录。
- 修复涉及代码或结论变化时，重新运行受影响的验证；存在 `blocker` 修复时，再次请审查者复核。
- 审查者与实现者意见不一致且无法收敛时，提交用户决定。
