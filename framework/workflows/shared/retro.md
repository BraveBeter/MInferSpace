# 共享子流程：复盘与知识沉淀

## 工作项复盘

结项前回答以下问题，结果写入 item.md 知识沉淀节：

1. 哪些发现对本项目后续工作有用？→ 写入 `knowledge/lessons.md`（或 `model.md`、`engine.md`），带来源工作项 ID 与日期。
2. 哪些发现与具体项目无关、可推广到其他模型或引擎？→ 标记为“候选晋升”。
3. 本次工作中，框架的流程、门禁、模板或工具有哪些不足（漏掉的步骤、无用的检查、含糊的描述）？→ 形成框架改进提议。

## lessons 条目格式

```markdown
### <日期> <一句话标题>（来源：<ID>）
- 现象：
- 原因（事实 / 推断）：
- 做法：
- 适用范围：
- 晋升状态：未晋升 / 候选晋升 / 已晋升到 <框架文件>
```

## 框架改进

- 框架改进提议写在当前工作项的知识沉淀节，或在工作区以 `docs/` 分支单独提出，说明问题、证据、建议修改。
- 用户批准后修改 `framework/`：在 [CHANGELOG.md](../../CHANGELOG.md) 记录并按语义化版本更新版本号；修改提交单独成组。
- 晋升到 `references/` 的条目须写明适用版本与核验日期。
- 已晋升的 lessons 条目更新晋升状态，保留原条目。
