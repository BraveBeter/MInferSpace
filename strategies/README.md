# 优化策略

这里记录每项优化的目标、起点、瓶颈证据、实现方案、实验与最终结论。顶层 README 提供表格索引，详细内容放在各策略目录的 `strategy.md` 中。

## 组织形式

```text
strategies/
├── README.md
├── OPT-0000-baseline/
│   └── strategy.md
└── OPT-0001-<简短名称>/
    └── strategy.md
```

以上策略目录仅为组织示例，具体策略在实际开展时创建。

- 策略编号使用 `OPT-0000`、`OPT-0001` 等，不复用编号；简短名称使用小写英文和连字符。
- `OPT-0000` 用于建立初始基线，记录其条件与适用范围。其他编号用于具体优化策略。
- 编号对应 `benchmark-results/OPT-xxxx/`；已有基线可跨策略引用原运行目录。
- 一项策略可以包含多个候选 commit 和多轮实验；独立假设或明显扩大的任务另起编号，并注明依赖关系。

## 基线推进

`OPT-0000` 使用 [固定的初始源码](../worktrees/README.md#固定的-baseline-起点)，通过统一评测建立性能锚点。保留其源码 SHA 和原始评测引用，用于后续累计收益比较。

| 当前基线策略 | 完整 commit | 已验收评测 |
| --- | --- | --- |
| 待建立（`OPT-0000`） | — | — |

- 叠加策略从上表登记的完整 commit 创建 worktree，记录前置策略、起点 SHA 和父基线运行。独立实验可以另选固定起点，在策略中说明原因和对照评测。
- 只有策略验收通过、实际受测 commit 可从保留的 Git 引用重新检出、评测和比较证据齐备时，才用候选更新上表。首次验收 `OPT-0000` 时登记初始基线。未接纳或已放弃的候选保留原策略记录。
- 默认以父基线评估边际收益。需要累计收益时，按 [评测比较规则](../benchmark-results/README.md#基线复用与对比) 另与 `OPT-0000` 比较，并链接各自报告。

“策略简述”用一两句话说明优化对象和核心方法，方便直接了解该策略准备做什么；目标与最终实测收益分别记录在策略正文和结果中。

状态沿用 `planned`、`profiling`、`implementing`、`benchmarking`、`decided`、`blocked`、`cancelled`，表示工作进展。最终决定单独记录为 `push`、`keep-local` 或 `discard`，并注明是否已经执行。

## strategy.md 内容

每项策略按以下内容组织：

1. **优化目标及起点**：目标场景和指标，源码路径、起点分支与完整 commit、候选分支及 worktree、模型与数据和环境引用、基线评测链接。
2. **瓶颈证据**：关联 profile 记录及关键观察，说明当前假设与依据，区分事实和推断。
3. **优化方案**：准备改动的内容与范围、预期收益及原因、风险和回退方式。
4. **实施与验证**：实施步骤、依赖关系、评测条件及正确性和性能验收标准。
5. **实验记录**：候选 commit、基线与候选运行、对比报告链接，以及每轮发现和下一步。
6. **最终结论**：实际收益与波动、正确性结果、适用范围、最终 commit，以及推送、保留本地或放弃的决定和执行状态。

运行事实和原始证据分别保存在 `profile-results/`、`benchmark-results/` 中，策略正文通过链接引用。

## 与 PLAN.md 的关系

[PLAN.md](../PLAN.md) 仅保留一张表，列为“策略编号、策略简述、状态进度、引用 strategy.md、起点 commit”，每项尚未完全验收的策略一行。引用使用指向实际策略文档的相对链接，起点记录完整 commit。

策略实现、评测并完全验收后，从 PLAN.md 删除对应行；没有待验收策略时仅保留表头和分隔行。详细历史和最终结论继续保存在本目录的策略文档及索引中。PLAN.md 不另写标题、说明或任务清单。
