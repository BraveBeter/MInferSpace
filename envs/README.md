# 环境管理

这里保存环境定义、实际环境及使用时的版本快照。按实际需求准备推理服务、评测客户端和离线评分环境；具体名称和安装方法在创建环境时确定。

## 组织形式

```text
envs/
├── README.md
├── specs/
│   └── <环境名>/             # 安装步骤、依赖文件或容器定义
├── snapshots/
│   └── <UTC时间>-<环境名>/   # 实际安装版本及相关运行环境信息
└── runtime/
    └── <环境名>/             # 本地 venv 等实际环境
```

以上是组织约定，子目录和环境按实际使用创建。环境名使用简短的小写英文和连字符，定义与本地环境使用对应名称；外部环境在下表登记实际位置。

## 文件与目录职责

- `specs/<环境名>/`：记录如何重建环境，包括安装步骤、依赖来源和必要的源码版本。依赖文件沿用实际使用的 pip、uv、Conda 或容器方式，无需同时维护多套格式。
- `snapshots/<UTC时间>-<环境名>/`：保存某次实际使用的 Python、依赖版本及相关 CUDA、驱动和硬件信息；容器按需记录 image digest。时间使用 UTC，例如 `20261117T120000Z`。具体快照文件格式在采集方式确定后落实。
- `runtime/<环境名>/`：保存本地 venv 等实际环境，属于可重建产物，不进入版本管理。外部 Conda 环境或容器保留原有位置，并登记定位信息。

环境定义说明如何安装，快照记录实际使用了什么。环境变更后生成新快照，保留旧评测所引用的记录；评测和 profile 的执行材料引用相应快照。

## 环境隔离

推理服务、评测客户端与离线评分按实际依赖决定是否拆分。基线和候选的可比评测引用同一份环境定义及对应的实际快照。editable 安装有源码互相影响的风险时，从同一环境定义分别重建运行环境，并在运行时核对实际加载的源码路径。
