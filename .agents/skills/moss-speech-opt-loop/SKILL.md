# moss-speech 优化工作流

在工作区根目录阅读 [AGENTS.md](../../../AGENTS.md)、[PLAN.md](../../../PLAN.md) 和当前阶段涉及的目录约定。已有策略从记录及实际证据确认进度，再继续对应步骤。只要求采集或分析时，完成第 1 步并交付。

## 1. 选定源码并做 profile

- 根据任务选定 sglang-omni 源码分支和完整 commit。核对实际检出、服务加载路径、环境与负载。参照 [源码与工作副本](../../../worktrees/README.md)。
- 优先复用已登记的 profile 脚本和配置。缺少采集能力时新增所需脚本或配置，按 [scripts](../../../scripts/README.md)、[configs](../../../configs/README.md) 和 [envs](../../../envs/README.md) 约定登记实际新增项。
- 按 [profile 归档规则](../../../profile-results/README.md) 保存执行材料、trace 或归档引用及分析，更新采集索引。用源码分支和完整 SHA 标识采集，可在任何策略建档前独立完成。

## 2. 根据证据立项

- 根据 profile 的观察提出可验证假设。证据不足时交付已知观察、限制和建议补采项；形成候选方案后分配策略编号。
- 根据 [策略约定](../../../strategies/README.md) 复制模板。链接已有 profile，写明起点、假设、预期影响、实验方法和对照基线。有现成可比运行时链接原始结果；基线待测时写明计划对照的提交和条件。
- 记录用户已经明确的保留条件和来源，未知项标为待用户说明。同步策略索引及 PLAN 中的新行。

## 3. 实现并验证正确性

- 从策略的固定 SHA 创建独立源码 worktree 和分支，并更新 [工作副本登记](../../../worktrees/README.md#当前已有工作副本)。阅读该检出的源码仓库规范，按 sglang-omni 开发者规范实现最小必要改动。
- 在策略记录实现范围、相关正确性测试和实际待测 commit。源码提交保存在 sglang-omni 仓库。同步阶段状态到策略索引和 PLAN。

## 4. 与基线做可比评测

- 按 [评测约定](../../../benchmark-results/README.md) 复用基线登记的环境、启动脚本、评测客户端或脚本、输入和负载。显式传入被测源码路径。可编辑安装相互影响时，从同一环境定义分别重建运行环境。
- 核对实际加载路径、commit 和 GPU 条件，独立于 profile 运行正式评测。候选使用可比的基线运行；缺少可比运行时先从策略起点按同样条件补测。首次建立约定的初始性能锚点时，在 profile 后登记 `OPT-0000`。
- 在策略编号下归档实际执行材料、客户端原生产物及比较报告。记录比较契约结论、失败或不完整运行，同步 benchmark 索引、策略实验记录及进度。

## 5. 按用户条件决定去向

- 按用户明确的保留条件逐项报告达标、未达标或证据不足，并链接依据。条件暂缺时可完成实现和评测。条件或去向尚待用户说明时，交付已得到的结果，按策略约定在策略索引和 PLAN 标为 `blocked`。
- 分别记录验收结论、用户决定的去向和执行状态。按用户授权执行保留、推送或放弃，并按工作副本约定处理资源。候选按用户条件达标、获明确接纳且证据齐备后，更新基线登记。
- 每个阶段结束时同步受影响的记录和索引；保留失败与阻塞的证据及恢复条件。结案后从 PLAN 移除对应项，保留策略和索引中的历史。交付前执行 [工作区检查](../../../scripts/README.md#工作区检查)。
