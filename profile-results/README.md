# Profile 结果

这里保存每次性能分析采集的原始产物、执行材料和观察记录。

## 组织形式

每次采集一个独立目录，按以下方式组织。下面的运行目录仅为示例，尚未实际采集：

```text
profile-results/
├── README.md
└── 20261117T120000Z-OPT-0001-nsys-baseline/
    ├── execution/       # 采集命令、配置、代码版本、环境和日志
    ├── traces/          # profiler 原始产物
    ├── exports/         # 按需导出的统计表、截图等
    └── analysis.md      # 本次采集的观察与分析
```

运行目录使用 `UTC时间-任务编号-工具-角色` 命名，例如 `20261117T120000Z-OPT-0001-nsys-baseline`。`nsys` 是工具示例，实际名称按所用 profiler 填写；任务编号对应关联的适配或优化任务，角色可使用 `baseline`、`candidate` 或适用的自定义名称。每次重新采集使用新目录，名称冲突时追加 `-02` 等后缀，保留已有产物。

目录按实际使用创建；没有导出材料时不必创建 `exports/`。

## 文件职责

- `execution/`：记录实际采集命令及工作目录、工具版本和配置、被测代码路径与分支及完整 commit、未提交修改情况、环境、输入负载、采集范围和日志。具体文件格式在选定 profiler 后确定。
- `traces/`：保留 profiler 生成的原始文件及其文件名，以便使用对应工具重新打开。
- `exports/`：按需保存统计表、截图等，并能够追溯到原始 trace 的事件或时间区间。
- `analysis.md`：说明采集目的、输入负载、关键事件或时间区间、观察到的瓶颈及待验证的假设；链接到原始证据、关联任务和相关 benchmark（如有）。区分观察事实与推断。

Git 忽略的原始 trace 通过仓库中的清单或归档说明引用，记录如何取回和打开。采集记录链接对应的 [任务正文](../tasks/README.md)。正式性能比较使用 [benchmark](../benchmark-results/README.md) 的独立评测结果，并注明相关采集与评测是否采用相同条件。
