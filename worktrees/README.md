# 源码与工作副本

目标仓库保留独立 Git 历史。将源码放在 `worktrees/<仓库名>/` 下，或在 [PROJECT.md](../PROJECT.md) 登记已有 checkout。每个目标仓库保留一个主克隆；基线或候选需要并行使用时，从主克隆用 `git worktree add` 建立独立副本。

- 开始前核对现有 checkout 的远端、实际提交和工作树状态。适配与优化的候选副本都从任务记录的完整起点提交创建。
- 记录工作副本实际路径、分支与起点。运行时确认实际加载的源码；依赖环境隔离见 [envs/README.md](../envs/README.md)。
- 结案时先保留受测提交与证据。清理前核对本地改动和其他任务或基线的引用。用 `git worktree remove` 的默认检查处理可清理的工作副本，并登记清理或保留结果。
- 基线以可取回的受测提交及其评测报告为依据。当前基线的入口由项目登记。

路径可用代码文本登记；可随 Git 取回的证据使用相对链接。
